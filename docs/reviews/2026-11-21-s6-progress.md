## 结论

战斗终局已经能落成存档并读回：`--run-level … --progress <file>` 在终局写一次（won/lost
都算一次 attempt），随后打印一份含 `totalStars/cleared/target` 的单行 JSON。不传该参数时
CLI 输出与改动前**逐字节相同**（两种形态各取 sha256 对比，见 §4.5），smoke 基线也**零差异**
（`95B0156A…`，32 个场景全等）。

两处必须记录的事实：

1. **`native/CMakeLists.txt` 有一行越界改动**（见 §2）。`pvz_progress` 库此前只挂在
   `progress_test` 上，`PvZ2SHUTTLE` 没有链接它，`--progress` 根本链不出来（`LNK2019` ×6）。
   只加了一个链接目标 `pvz_progress`，没有改任何编译选项、源文件列表或测试注册。
2. `sun_used / sun_produced / plants_lost / time_limit` 四类星章目标在 `evaluateStars` 里
   恒判 false（`native/src/progress.cpp:241-244` 的注释已写明理由：打开会改动 67 关的星章，
   属设计决定）。本次**没有**打开它们，所以 beach_23 的 `kill 10` 依然不可达，胜利是 2 星。

## 4. 验收

### 4.1 beach_23 脚本胜利 = 2 星

`content/stars.json` 的 beach_23 是 `beat` / `mowers(value=5)` / `kill(count=10)` 三条；
该关 `waves[0].zombies` 只有 1 只，所以 `kill 10` 结构性不可达（`testStarGoalsReachable`
已把 67 个同类目标钉住）。脚本局 5 辆推车全在 → `mowers` 通过 → **beat + mowers = 2 星**。

```
> PvZ2SHUTTLE.exe --run-level content beach_23 --script native/tests/scripts/beach_23_win.json --seconds 120 --progress "…\存档 二\进度.json"
{"boss":"","bossActionUnwired":0,"bossSpawned":false,"bossStages":0,"bossUnavailable":0,"cols":9,"fusions":0,"hash":"0x4c51cda0ba55946f","killed":1,"leaked":0,"level":"beach_23","mowerKills":0,"rejectedSpawns":0,"removed":0,"rows":5,"spawned":1,"status":"won","sun":50,"tick":1597,"unwiredPlants":0,"unwiredZombies":0,"waves":1}
{"cleared":1,"levels":{"beach_23":{"attempts":1,"bestTick":1597,"cleared":true,"goals":[true,true,false],"stars":2,"target":3}},"totalStars":2}
```

（第一行是既有的 `summarize`，逐字节未变；第二行是新增的进度报告。）

### 4.2 同关再打一次：星章不减、attempts 递增、bestTick 取更快

beach_23 不带脚本跑 400 s 会靠推车吃掉唯一的僵尸（`mowerKills=1`），这是「赢了但丢车」，
`mowers` 星章当年已得（`goals` 只做 OR 折叠，不回退）：

```
{"cleared":1,"levels":{"beach_23":{"attempts":2,"bestTick":1597,"cleared":true,"goals":[true,true,false],"stars":2,"target":3}},"totalStars":2}
```

真正的失败局用 frontyard_1（无防守 → 漏怪）：

```
{"cleared":0,"levels":{"frontyard_1":{"attempts":1,"bestTick":0,"cleared":false,"goals":[false,false,false],"stars":0,"target":3}},"totalStars":0}
{"cleared":0,"levels":{"frontyard_1":{"attempts":2,"bestTick":0,"cleared":false,"goals":[false,false,false],"stars":0,"target":3}},"totalStars":0}
```

「更快才压低 bestTick」由 `testRecordBattleKeepsTheBestRun` 覆盖：先 1597 胜 → 造一个
`tick=1097` 的**失败**（bestTick 保持 1597）→ 再 `tick=1297` 的胜利（bestTick 变 1297），
attempts 1→2→3。
