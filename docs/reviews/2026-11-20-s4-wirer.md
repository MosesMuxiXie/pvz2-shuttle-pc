## 2. 视图改造

`battle_view.hpp` 不再 include `simulation.hpp`，改为 `#include "catalog.hpp"` + `#include "engine/world.hpp"`：

```cpp
namespace pvz {
struct PlayScriptOptions { std::filesystem::path pack, boards, script; double seconds = 30.0; std::filesystem::path snapshot; };
void runBattlePreview(const Catalog&, const std::filesystem::path& assetRoot, bool smokeTest = false,
                      const std::filesystem::path& snapshot = {}, std::uint32_t seed = 1);
void runPlayScript(const Catalog&, const LevelDefinition&, const PlayScriptOptions&);
}
```

`battle_view.cpp` 内部是 `class BattleScene`：成员持有 `engine::World`（`std::unique_ptr`）与渲染资源，
`drawFrame()` 只读 `world_->snapshot()`（`plants/zombies/shots/suns/mowers/status/tick/sun/wave/waves/rows/cols`），
不再有 `std::make_unique<Battle>`、写死 `plant("sunflower",0,0)`、每 60 tick 自动收阳光之类的伪逻辑。

构造函数成员顺序是**载重**的：`display_` → `lawn_, sunArt_, panelArt_` → `assets_` → `text_`。
`AssetCache` 对缺失目录会先抛 `missing asset root`，把美术解析放在它前面，缺美术目录才会得到测试要求的
`...\lawn\frontyard.png: missing battle lawn`。

## 3. 交互与 HUD

- 卡槽 = `level.deck`（空则用世界默认四卡），点击选中并高亮，再点格子 `world_->plant(type,row,col)`。
- 失败原因串走 `localized()` 上屏（`not-in-deck`/`cooling down`/`not enough sun`/`cell occupied`/`cell out of bounds`/
  `too many plants`/`level finished`），冷却按 `world_->cooldown(type)` 与 `tick()` 画进度条，阳光不够画灰。
- 右键或铲子按钮 `world_->shovel(row,col)`；点阳光 `world_->collect(id)`（`Snapshot::suns` 带 id/x/y）；
  空格 `world_->pause(bool)`。
- HUD：阳光、`第 wave/waves 波`、`剩余僵尸`（`zombies()` 里 `alive` 计数）、`状态：战斗中/胜利/失败`、
  `0:SS · tick N`；右上角铲子/暂停按钮，底栏操作提示。全部中文文案。

## 4. `--play-script`

```
--play-script <content> <levelId> [--pack P] [--boards B] [--script S] [--seconds N] [--snapshot out.png] [--assets DIR]
```

构造 `engine::World world(catalog, level, script.seed)`，`engine::runScript(world, script, seconds)` 之后
`engine::summarize(world)` 再加三项本 CLI 自己的计数（`planted/collected/shoveled` 由 `applyInputs` 的返回值累计，
`rejectedInputs/snapshot/snapshotBytes/seed/plants/shots/suns/zombies` 由 `World` 查询补上）打印单行 JSON。
`--assets` 可省：省略时按 `cwd`、`<content>/..`、exe 邻近的候选顺序找美术根，只为截图；找不到就只输出 JSON。

脚本格式沿用 `engine/replay.hpp`：`{"level","seed","inputs":[{"tick","op":"plant|collect|shovel|spawn","type","row","col","id"}]}`，
`op:"collect"` 且 `id:0` 表示收齐全部阳光。

`native/tests/scripts/play_frontyard.json`：sunflower(2,0)@10 → 同卡再种一次@12（应被冷却拒绝）→ potatomine(3,4)@40 →
spawn basic row 2 @200 → collect 全部 @280 → peashooter(2,2)@320 → wallnut(2,5)@340（此时 0 阳光，应被拒绝）。

## 7. 已知差距与风险

1. **无真人交互验证**：交互态（点卡/点格/铲子/暂停）只由代码路径覆盖，没有自动化点击；`--play` 需要窗口，
   本次只验证了 headless 的 `--play-script` 与 `--battle-snapshot`。鼠标命中框（棋盘几何、卡槽、按钮）与旧版一致，未回归。
2. **截图只在 1280×720**：`sdl::Display` 固定 logical presentation，其它分辨率未测。
3. **`--play-script` 的时间预算**：`--seconds` 默认 30 s（1800 tick）；脚本里超过该 tick 的输入不会执行，也不会报错。
4. **构建告警**：`native/src/engine/world.cpp(339) warning C4244`（double→int64_t 截断）在本次构建里出现，
   属于 engine 文件（不在本任务写作用域），仅告警，不影响 16/16 通过；留给 S2 内核审核项跟进。
5. **契约路径偏差**（见 §1）需要 reviewer 按实际文件名核对：`native/tests/battle_view_test.cpp`（ctest `battle_render`）、
   `build\s4-wirer\Release\PvZ2SHUTTLE.exe`。
