# S4 闭环：菜单 → 关卡 → 战斗 → 结算 → 回地图（t45 / T46）

日期：2026-11-24。写作用域：`native/src/flow.{hpp,cpp}`（新）、`native/src/main.cpp`（`--flow` 分支、`--menu` 的 `level`/`--flow-after`、help）、`native/tests/flow_test.cpp`（新）、`native/CMakeLists.txt`、本文件。`progress.*` 未改（`lastLevel` 由队长在上一轮加进 `Progress`，我只消费）。

## 一句话

三屏原来各画各的：主菜单只知道存档有几颗星，关卡列表只知道某个 world 有哪些关，战斗不知道自己赢了之后该写进哪一行。这一轮把「下一关是哪个」抽成一个函数（`pickNextLevel`），让 `--menu` 与 `--flow` 都调它，并把「打完一场 → 落进存档」合成一条无头命令，于是「主菜单 → 世界地图 → 关卡 → 战斗 → 结算 → 回地图」可以在没有窗口的情况下被逐字验证。

## 改了什么

### `native/src/flow.hpp` / `flow.cpp`（新）

| 函数 | 作用 |
| --- | --- |
| `levelsOfWorld(catalog, world)` | 该 world 的关卡 id，按关卡自身的 `index` 排序，同序按 id |
| `starterWorld(catalog)` | 世界地图顺序（`content/worlds.json` 的 `order`）里第一个**有关卡**的世界 → `frontyard` |
| `pickNextLevel(catalog, progress, lastLevel)` | 有 `lastLevel` 就进它的 world（不认得的 id 回退到 starter），再取该 world 第一个「没有记录或未通关」的关卡；全通则回第一关并置 `allCleared` |
| `playPickedLevel(...)` | 建 `engine::World` → `runScript` → `outcomeOf` → `evaluateStars` → `recordBattle`，回读记录 |
| `runFlowCycle(...)` | `pickNextLevel` + `playPickedLevel` |

两个刻意的选择：

1. **`starterWorld` 用世界地图顺序，不用关卡 id 排序。** 我第一版取「最低 `index` 的关卡的 world」，同 index 时按 id 比较 → 得到 `beach_1`（`beach` 字母序在 `frontyard` 前面），`flow_test` 立刻红：`two finished levels must leave the third (frontyard_3), got beach_1`。新存档只能从 `frontyard` 开始，所以顺序必须来自 `worlds.json` 的 `order`。
2. **未通关就重打，不跳过。** 「首个未通关关卡」在输掉/中途退出后仍是同一关——这是玩法，不是 bug；推进只在真的打赢之后发生。

`FlowResult` 的 `stars` 是**这一场赚到的**星（结算界面的数字），`levelStars` 是该关存档里的最好成绩，`json()` 把两者都输出，测试里也分开断言。

### `native/src/main.cpp`

- `--flow <content> [--pack] [--boards] [--script] [--seconds] [--progress] [--assets]`：读存档 → `runFlowCycle` → **整轮结束后**才 `saveProgress`（崩在中途不能让下一轮跳过没打的关）→ 单行 JSON。
- `--menu` 在 `choice == "continue"` 时补一个 `level` 键（`pickNextLevel(...).level`），此前只返回 `choice`，调用方无法知道续到哪一关。
- `--menu ... --flow-after`：菜单返回 `worldmap` 之后再跑一轮 `runFlowCycle`。`--menu` 是一次独立调用（`runMainMenu` 已经返回、窗口已关），不是在一个进程里并行两套事件循环；`--flow-after` 的存在只是让脚本少写一条命令。
- `--seconds` 的解析原本是 `--run-level` 里的局部 lambda，`--flow` 用不到它；提成文件作用域的 `parseSecondsValue`（仍然校验 `[0, 86400]`）。
- 顺手修了 `--audio-off` 在 `wmain` 下的编译错误：`std::string(argv[i])` 不能接 `wchar_t*`（`main.cpp(634,33): error C2664`），改成 `#ifdef _WIN32` 用 `std::wstring`。

### `native/tests/flow_test.cpp`（新，9 个用例）

`testFirstPickStartsTheStarterWorld`、`testPickFollowsTheSavesLastLevel`、`testPickIgnoresALastLevelThatIsNotALEvel`、`testPickSkipsFinishedLevels`、`testPickReplaysTheFirstLevelWhenEverythingIsCleared`、`testSaveCarriesTheLastLevel`、`testWonBattleLandsInTheSave`、`testTwoTurnsMoveForward`、`testDamagedSaveIsNotOverwritten`。

`testTwoTurnsMoveForward` 是这条链路的主断言：空脚本打不完一关 → 第二轮必须重打同一关（并记一次 `attempts`）→ 把那一关按「赢」写进存档 → 第三轮必须开到下一关，且 `progressReport` 的 `totalStars`/`cleared` 不得倒退。

`testWonBattleLandsInTheSave` 用 `beach_23_win.json` 真赢一场（`status == "won"`、`cleared == true`、`levelStars >= 1`），再走 `saveProgress` → `loadProgress` → 记录与星数仍在。

### `native/CMakeLists.txt`

`pvz_flow`（`src/flow.cpp`，PUBLIC `pvz_progress`）+ `PvZ2SHUTTLE` 链接 `pvz_flow` + `flow_test`（`add_test(NAME flow ... "${PVZ_TEST_CONTENT}" "${PVZ_TEST_TEMP}" "${CMAKE_CURRENT_SOURCE_DIR}/tests/scripts")`，TIMEOUT 180）。

### `--menu` 的「继续游戏」现在说得出续哪一关

```
& PvZ2SHUTTLE.exe --menu content --progress $env:TEMP\flow-demo2.json --assets <assets> --snapshot x.png --frames 1
{"choice":"continue","level":"beach_23"}
```

存档里 `lastLevel = beach_22`、前 22 关已通关 → `beach_23`，正是 `pickNextLevel` 的规则（先跟随 `lastLevel` 的 world，再取首个未通关）。

### `--flow-after`：菜单之后接着跑一轮

空存档：

```
& PvZ2SHUTTLE.exe --menu content --progress $env:TEMP\flow-after.json --assets <assets> --snapshot x.png --frames 1 --flow-after
{"choice":"worldmap","flow":{"cleared":false,"lastLevel":"frontyard_1","level":"frontyard_1","levelStars":0,"stars":0,"status":"lost","tick":8038,"world":"frontyard"}}
```

`--menu` 之后 `runMainMenu` 已经返回、窗口已关，`--flow` 是第二次独立调用，不是两套事件循环并行。

### 两次 `--flow`：第二轮自己走到下一关

存档先摆成「`beach` 世界前 22 关都打完、`lastLevel = beach_22`」的玩家（`%TEMP%\flow-demo2.json`）：

```
& PvZ2SHUTTLE.exe --flow content --progress $env:TEMP\flow-demo2.json `
    --script native/tests/scripts/beach_23_win.json --seconds 600
{"cleared":true,"lastLevel":"beach_23","level":"beach_23","levelStars":2,"stars":2,"status":"won","tick":1597,"world":"beach"}

# 同一条命令、同一个存档，再跑一次
{"cleared":false,"lastLevel":"beach_24","level":"beach_24","levelStars":0,"stars":0,"status":"lost","tick":8038,"world":"beach"}
```

第一轮打赢 `beach_23`（2 星，1597 tick），第二轮没有被告知「下一关是哪一关」，自己从存档里的 `lastLevel` 走到 `beach_24`——这就是闭环的证据。跑完存档里 `lastLevel = beach_24`、`levels` 24 条、`cleared` 23 条、星数合计 68。

空存档时（`--progress` 指向不存在的文件）第一轮落在 `frontyard_1`：

```
{"cleared":false,"lastLevel":"frontyard_1","level":"frontyard_1","levelStars":0,"stars":0,"status":"lost","tick":9220,"world":"frontyard"}
```

> 上一版本文件里记的 `beach_23` tick 是 1536；数值随上游引擎改动（同一天里 `action_runner.cpp` 等被改过）会变，同一次构建内同一存档两次运行是逐字一致的。

### 发现：`lastLevel` 只在存档带 `seeds` 数组时才读得到（`progress.cpp`，不在本轮写作用域）

`native/src/progress.cpp:283-296` 把 `lastLevel` 的解析写在了 `seeds` 的 `if` 里面：

```cpp
283:   if (const auto seeds = json.find("seeds"); seeds != json.end() && seeds->is_array()) {
...
290:     if (const auto last = json.find("lastLevel"); last != json.end() && last->is_string()) {
291:       progress.lastLevel = last->get<std::string>();
292:     }
...
296:   }
```

`saveProgress` 一定会写 `seeds`（`progressToJson:353-357` 无条件写空数组），所以「存了再读」的往返永远看不出问题——`flow_test` 的 `testSaveCarriesTheLastLevel` 正是因为数据来自 `saveProgress` 才通过。但**没有 `seeds` 键的存档**（手写的 fixture、别的语言的写盘、早期版本留下的文件）会静默丢掉 `lastLevel`：

```
# lastLevel = beach_22，没有 "seeds" 键
{"choice":"continue","level":"frontyard_1"}      ← 错，应为 beach_23

# 同一份存档加上 "seeds": []
{"choice":"continue","level":"beach_23"}         ← 对
```

`--flow` 同样会「忘记」下一关、从头开始，且不会报错。修法是把 290-292 行移出 `seeds` 的 `if`（放在 `keys`/`coins` 之后、`levels` 之前），并在 `progress_test` 里加一条「有 `lastLevel`、没有 `seeds`」的读取用例。`progress.*` 由队长维护，本轮没动。

## 还没有的东西

- **选卡界面**：`--flow` 用空脚本（或 `--script` 给的固定输入）打，没有「给你一列种子、你挑」的那一屏。关卡 deck 在 `content/levels/*.json` 里已经有了，缺的是 UI 与「选中的种子带进战斗」这条接线。
- **结算界面动画**：`FlowResult` 已经是结算屏需要的全部数字（星、`tick`、清没清），但没有画那三颗星飞出来的屏；`--flow` 的 JSON 就是它的数据面。
- **商店 UI**：`pvz_shop`（`--shop`）能买，`Progress.purchases/seeds` 也在存；没有进店的那一屏，也没有「买了的种子出现在选卡列表里」这条链。
- **`--menu` 的 `--flow-after` 只跑一轮**：一轮之后仍是「回到地图」，不是连续刷关的循环。要做循环得先有结算屏来决定「下一关还是重打」，现在这个判断在 JSON 里，不在画面上。

## 维护提示

- `pickNextLevel` 是唯一决定「下一关」的地方：`--menu` 的 `continue`、`--flow`、未来的结算屏都必须调它，否则三处会各说各话。
- `starterWorld` 依赖 `content/worlds.json` 的 `order`；新增世界时 `order` 必须连续，否则新存档可能从半路开始。
- `saveProgress` 只在整轮结束后调用。将来加「中途存档」时，注意别在战斗开始时就把 `lastLevel` 写进去，否则崩了以后这一关会被当成已打过。
- `progress.*` 的 `lastLevel` 解析目前依赖 `seeds` 键存在（见上一节的复现）。谁改 `progress.cpp` 时顺手修掉它，否则「手写存档」这条路会一直静默丢掉下一关。
