# 恢复记录（2026-11-23 08:10）

## 恢复时的真 blocker：环境变量大小写重复

所有构建在恢复后都起不来，报 `CMake Error at CMakeLists.txt:2 (project): No CMAKE_CXX_COMPILER could be found`。
工具链没问题（`vswhere` 正常返回 BuildTools，`cl.exe 14.44.35207` 在位）；根因在
`CMakeFiles/CMakeConfigureLog.yaml` 里写得很清楚：

```
error MSB6001: Invalid command line switch for "CL.exe".
System.ArgumentException: Item has already been added.
Key in dictionary: 'NO_PROXY'  Key being added: 'no_proxy'
```

宿主环境块里 `NO_PROXY` 与 `no_proxy` 同时存在。MSBuild 的 CL 任务把环境复制进大小写不敏感的
Hashtable，第二个键直接抛异常，于是编译器识别阶段就失败，连 `cl.exe` 都没真跑。
`tools/build_native.ps1` 原来只 `SetEnvironmentVariable('no_proxy', $null)`——删一个名字删不掉重复项。

修法（`tools/build_native.ps1`）：
1. 枚举 `[Environment]::GetEnvironmentVariables().Keys`，把只差大小写的名字收敛成一份；
2. 用 `ProcessStartInfo` 以**重建后的干净环境**启动 cmake / msbuild / ctest（PowerShell 的 `&` 会原样传
   原始环境块，所以只在脚本内清理没用）。

顺带修掉自己引入的两个 bug：`Invoke-Native` 里 `Write-Output` 会把子进程输出混进返回值，导致
`(Invoke-Native ...) -ne 0` 变成数组比较、永远看起来是假（第一次"成功"其实是假绿）；以及
在返回的 .NET Process 上挂 `ErrorDataReceived` 事件在本宿主里不可用。现在改为同步读两条流 + `Write-Host`。
