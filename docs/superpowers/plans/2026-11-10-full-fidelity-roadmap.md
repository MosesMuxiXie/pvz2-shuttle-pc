# PvZ 2 SHUTTLE v26.10.1 高精度复刻路线图

## 目标与当前基线

以 Android 版 `26.10.1`（versionCode `460`）为固定对照。C++20／SDL3 客户端覆盖可确认的原版玩法、进度、界面、美术、音频和联网能力。开发期间保留 Python 版作回归基线，原生版满足发行条件后统一切换。交付目标为 Windows 10/11 x64 安装包和便携包，以及 macOS 11+ Universal 2 DMG。沿用已确认的 macOS 验证范围，由 GitHub Actions 验证构建、双架构、镜像和包内结构。

基线为 `feature/native-client` 的 `4b37b62`。已有原生内容审计、前院第 1 关、Python v2/v3 存档导入和 macOS 开发 DMG。前院首关的 50 基础阳光、12 秒首波与六波构成有静态证据。动态刷波、叶绿素、原版素材和界面仍需实现或校准。现有 26 世界、1,809 条关卡是待核对的桌面目录，其中有 163 条合成记录和 45 条砸罐子记录。最终关卡范围以 APK 中可达入口与同版 OBB 对照表确定。 [原生设计](../specs/2026-11-10-native-client-design.md) · [首关证据](../specs/2026-11-10-frontyard-apk-evidence.md) · [开发构建](../../../native/README.md)

## 实施顺序与退出条件

| 阶段 | 工作内容 | 达标后进入下一阶段的条件 |
| --- | --- | --- |
| 0. 建立原版证据与关卡索引 | 贯通 APK 菜单、世界、章节、模式、OBB `LevelDefinition`、模块别名和桌面 ID。逐条标记可达、隐藏、活动、重复、缺依赖或待核验。为样本录制输入、状态、画面和音频。 | 有可审阅的关卡清单，旧版 163 条合成记录及 45 条砸罐子记录均有处置状态。静态与动态证据可以追溯到同一版本。 |
| 1. 把前院首关做成标准样板 | 完成固定步长事件轨迹，补随机落阳光、按波次血量提前刷怪、旗帜警告、第五波叶绿素和选卡进度规则。核对种植冷却、护甲、伤害、胜负和重试。 | 可用同一输入回放胜、负、暂停和结算。确定性事件逐项匹配，随机分支按已证实的范围和条件验证。留存原版对照以及 C++ 回归样本。 |
| 2. 扩展引擎与批量导入 | 统一解析场地、卡组、传送带、潮汐、轨道、预摆、目标、波次、保护植物和奖励等模块。实现角色特性、元素反应、Boss、砸罐子、无尽及其他小游戏。使用原版有效引用和数据规则生成每关，按模块组合复用实现。 | 全量关卡能导入、索引、正确路由并初始化。每类机制、Boss 阶段和关键组合有行为测试及胜负回放。无法解析或缺行为的条目在矩阵中有具体原因。 |
| 3. 重建完整游玩流程与表现 | 接通启动器、世界图、关卡选择、图鉴、商店、装扮、花园、融合、设置和点歌机。还原资源加载、图层、骨骼、特效、字幕、音乐转场与循环。补齐奖励、重复通关和旧档迁移。 | 原版主要流程、控制和状态切换可逐屏对照。发布范围内的资源引用有完整性校验，使用占位或替代素材的条目有明确状态。存档备份、失败恢复和重复操作通过。 |
| 4. 核验并接入联网功能 | 与阶段 1–3 并行调查版本、公告、资源下载、登录、云档、任务及活动。为支持桌面接入的服务实现超时、缓存、重试、断网、会话过期和冲突处理。 | 每项服务有已验证可接入、经验证不可接入或待核验状态。可接入功能有端到端记录，明确不可接入项进入发行说明。 |
| 5. 发布候选与回归 | Windows 生成原生安装包和便携包，验证干净安装、升级、档位保留和卸载。GitHub Actions 生成 macOS Universal 2 DMG，核对 Mach-O、镜像、包内容与校验和。执行长局、重复进出关、低分辨率和存档恢复检查。 | 发布范围内的关卡、核心机制、资源和可接入联网功能达到覆盖要求。候选包与源码、数据版本和 SHA-256 一一对应。版本说明列出经确认不可接入的服务及已知差异。 |

阶段 0 与阶段 1 可同时启动。联网调查和原版素材盘点也可提前开展。最关键的依赖链是**原版证据 → 首关对照样板 → 通用模块 → 全量内容 → 发布验收**。新增世界优先选能覆盖不同场地规则、Boss 或小游戏的代表关，验收后再扩到同类关卡。若同版运行表现与静态默认值不同，记录档位、难度、入口和覆盖配置，先区分默认值与运行时覆盖，再校准桌面实现。

## 如何判定高精度

- **每关都有核验记录。** 至少保存原版入口、OBB 包与模块、C++ 定义、依赖素材、验证状态、差异及可重跑的证据。全量执行结构、引用、路由和初始化检查。每类机制及组合做实际回放，单独标记只有静态证据的条目。
- **玩法按事件对照。** 记录选卡、放置、费用、首波、刷怪、伤害、掉落、胜负与奖励的顺序及时间。固定输入、随机种子和时钟用于 C++ 回归。原版种子无法控制时，记录多个样本，按确认的触发条件、时间范围及分支结果对比。
- **画面和声音按同场景对照。** 统一语言、视口和操作状态，对照位置、尺寸、图层、动画关键帧、触发音效、转场和循环点。先从首关样本确定可重复的测量方法，再设定各类允许误差。
- **平台验证可复跑。** Windows 覆盖窗口、全屏、高 DPI、30/60/120 帧显示和长局稳定性。macOS CI 检查双架构、部署目标、依赖、包内资源和镜像完整性，沿用无需执行应用的验收范围。
- **存档和联网按状态变化对照。** 测试新档、旧档、损坏档、导入后重开、重复领奖、重连和冲突。记录每步的预期结果。公开服务状态写核验日期、实际行为和接入条件。
- **状态分开记。** 建议使用 `待取证`、`静态核对`、`已实现待对照`、`已对照通过`、`已确认不可接入`。覆盖率按阶段分别记录，保留原版证据和桌面结果。
