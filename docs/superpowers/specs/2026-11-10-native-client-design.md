# PvZ 2 SHUTTLE v26.10.1 原生客户端重建

## 目标和边界

在同一仓库内独立重建 Windows 和 macOS 原生客户端。用户选择一次性切换到完整 C++ 客户端，并将原版联网功能纳入范围，逐项核验服务可用性。开发过程允许分阶段实现和验收。正式发布物统一使用原生客户端，涵盖启动、内容加载、玩法、界面、渲染、音频、存档与联网，不依赖 Python 或 Android 运行时。现有 Python 版作为测试基线，已有素材提取和内容生成脚本作为离线开发工具。

Windows 延续现版的 Windows 10/11 x64 目标，交付安装程序和便携包。macOS 延续 macOS 11+、Intel 和 Apple Silicon 的目标，交付包含 Universal 2 `.app` 及 `Applications` 快捷入口的 `.dmg`。最低系统版本须经依赖构建和实际启动验证。

## 重建路线

| 路线 | 实施影响 |
| --- | --- |
| 在现客户端中分批替换 Python 模块 | 较早获得可玩的中间版本，需要维护两套运行时的接口和生命周期。 |
| 独立实现 C++ 客户端，完整后切换（已选） | 原生架构统一。新旧客户端通过相同数据、测试输入、存档和运行结果对照，功能达标后切换发行入口。 |

建议采用 C++20、CMake、CTest 和 SDL3。核心模拟库负责格子、实体、波次、场地、碰撞、状态、奖励和特殊模式，不依赖图形。运行时以固定步长推进，显示帧率可独立设为 30、60、120 或自适应。可注入随机种子和时钟，输出结构化事件轨迹。上层负责状态导航、输入映射、高清缩放、DragonBones 绘制、文字布局和音频。按需选择固定版本的 SDL 扩展和 JSON、TLS 客户端依赖。Windows 用 MSVC 构建，macOS 用 Apple Clang 构建两种架构并检查所有随包动态库。 [SDL CMake 文档](https://wiki.libsdl.org/SDL3/README-cmake)

保留现有 JSON、素材键和存档作为过渡输入。统一资源目录解析及别名验证，为每个原版关卡保留 OBB 标识、规则来源和覆盖状态。未知规则应在审计中显式出现。存档使用带版本的读取器，覆盖现有 Python 版版本 2/3、旧版进度、世界解锁、购买和花园状态，导入时保留原件并在完成验证后原子写入。Android 存档兼容性需独立取得可读取样本后验证。

- Windows 隔离副本使用本地素材，`validate_all.py` 为 0 错误、0 警告，8 个测试脚本中 7 个通过，`main.py --selftest` 通过。`test_integration.py` 在 90 秒后断言仍有植物，复测显示点击实际种下了向日葵并扣除 50 阳光，但 90 秒后植物数量为 0。该用例应分别验证成功种植和后续战况。只有源代码的检出副本因素材缺失报 3 个错误、177 个警告。当前 Windows 主机可用 MSVC 14.44 和 CMake 3.31.6。

## 联网服务核验和实现条件

2026-11-10 使用正常 HTTPS 请求验证官网、公告列表和公开版本 JSON 均返回 HTTP 200。`czok.json` 返回 `ver=122` 及 `needDeleteOld`、`downloadUrl` 字段。版本 JSON 代表原版服务的版本或内容信号，不能当作桌面程序的更新版本号。客户端应用和游戏内容分别建版本策略，保留证书及主机名验证。 [官方站点](https://www.pvz2shuttle.cn/?lang=zh-CN) · [更新入口](https://pvz2shuttle.cn/cz/czok.json)

| 服务 | 现有证据 | 确认可用的标准 |
| --- | --- | --- |
| 版本、新闻及更新提示 | 公开入口已确认可访问。Python 仅有后台查询。 | 用正常 HTTPS 获取并校验结构，覆盖缓存、异常数据、网络失败、原版更新跳转和桌面端更新区分。 |
| 资源下载 | 本地匹配 OBB 与原版下载服务组件存在。公开版本 JSON 有下载字段。具体下载载荷与运行时资源下发未核验。 | 用公开或明确支持的下载入口取得匹配版本，校验完整性，验证恢复下载和原子切换。 |
| 登录与账号 | 清单含 SDK 认证组件，原版是否提供玩家可见登录以及服务是否开放尚未确认。 | 同版原版 UI 可复现，确认支持的认证方式和客户端资格，再用测试账号验证退出、过期及重登。 |
| 云存档 | 当前桌面端为本地 JSON。原版实际入口、读写协议、是否支持桌面端均待确认。 | 用独立测试档验证上传、还原、冲突和离线恢复。 |
| 限时活动、任务、奖励 | 公告有版本任务和活动，OBB 含日历/活动类配置。在线日程与奖励是否依赖服务仍待确认。 | 区分本地配置与在线数据，验证时区、活动状态、奖励领取和重复领取保护。 |
| 计费、广告及其他 SDK | 清单存在相关 Android SDK。实际是否向玩家暴露及是否可在桌面使用待确认。 | 先用原版正常流程验证对应入口和依赖，再决定受支持的桌面集成方式并记录证据。 |

联网接口通过独立适配层注入，可回放已观察到的响应并测试错误场景。模拟响应只作为测试证据。服务若未开放或不可用，记录对应操作、验证时间、表现和依赖，并按原版可观察行为提供明确状态。玩家的离线进度应能独立加载和保存。需要写入服务器的验收使用独立测试账号和测试档。

## 工作顺序与发布标准

1. 锁定 APK、OBB、素材及 Python 基线版本和可复验的样本。用 Craft Anything 保存包清单和证据，补齐可运行 26.10.1 的 Android 设备/录屏。捕获同版主要场景和特殊机制，标注设备、分辨率、语言、帧率、存档与状态；为每个关卡与玩法归类。
2. 新建原生入口和双平台构建，完成内容加载、固定步长模拟、首个前院关从选卡到结算以及 Python 存档导入。首个关卡作为技术验收样本，后续内容在同一原生架构补齐。
3. 扩展关卡模块、实体、地图、小游戏、Boss、成长、界面、动画与音频。用固定随机种子和输入脚本比较逻辑事件，用相同视口和语义状态比较布局、关键帧、动作及音轨。遇到原版行为与旧桌面版不同时，以可验证的原版行为为准。
4. 实现并测试已确认的联网服务。完成全量内容结构校验、各模块回放和 UI 对照。验收矩阵为每项记录原版证据、桌面结果、差异与覆盖状态。没有原版证据的项标为待核验。
5. 在 Windows x64 和 macOS 两种架构上执行安装、启动、游玩、存档和卸载冒烟测试。Windows 复用 Inno Setup 发行入口。macOS 在 macOS 构建机上通过 CPack DragNDrop 生成 DMG，运行 `hdiutil verify` 和挂载复制测试，使用 `lipo -archs` 检查可执行文件及动态库，测试从 `/Applications` 正常启动。公开发布需要 Developer ID 签名、公证和 Gatekeeper 验证。发布素材维持仓库既有来源和授权边界。 [CPack DMG](https://cmake.org/cmake/help/latest/cpack_gen/dmg.html) · [Apple 分发流程](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

原版对照覆盖、联网能力状态、安装物及其平台测试记录共同决定发布状态。用户确认对已证实停服、未开放或不支持桌面接入的功能在发行说明中明确标注。已确认可接入的联网功能要求端到端验收，仍待核验的服务不能视为已完成。ADB 设备、可用于验证的平台和服务测试账号可以在对应阶段补齐。
